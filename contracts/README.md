Сгенерированные JSON хранятся в репозитории для прямого использования другими участниками. Работающий `/openapi.json` встраивает эти схемы для Swagger; установка и Docker описаны в корневом README.

2. **Объекты и смысл полей.**

| Объект | Назначение |
|---|---|
| Project | Название проекта и указатель на актуальную версию брифа |
| BriefInput / BriefVersion | Ввод пользователя, ограничения, неизвестные, исключённые источники; версия и автор правки |
| Capability | Возможность продукта: доступна, запланирована или гипотеза; основание статуса |
| Source | Происхождение данных, адрес, доступный фрагмент, место в документе и даты |
| Claim / Evidence | Утверждение и фрагменты, которые поддерживают его, противоречат ему или дают контекст |
| StrategyOption | Сегмент, проблема, ценность, приоритеты, ресурсы, каналы, возражения и условия отказа |
| Message | Сообщение для конкретного варианта, связи с возможностями и утверждениями, допустимость обещания |
| Experiment | Проверяемая гипотеза, метод, метрика, порог решения, данные и условие остановки |
| Decision | Выбор, отказ или запрос доработки и автор решения |
| ReviewIssue | Замечание, важность, затронутая версия объекта, основание, способ исправления и этап возврата |
| Run | Статус выполнения, этап, версия брифа, ревизия состояния и статус качества |
| Artifact | Сохранённый результат этапа: ссылки на версии сущностей, зависимости, модель и промпт |
| Usage | Одно событие использования провайдера/инструмента, его стоимость и основание расчёта |
| Snapshot | Согласованный снимок проекта, брифа, запуска, данных, артефактов, вопросов и использования |

Все описанные поля обязательны. Неизвестное значение обозначается `null` только там, где это разрешено схемой. Пустой список обозначает отсутствие элементов; его нельзя заменять текстом «нет». Дополнительные поля запрещены. Изменение формата проходит через владельца A1.

ID — непрозрачная строка; клиент не извлекает из неё смысл. Версии начинаются с 1. `(kind, id, version)` идентифицирует версию содержательного объекта. DataBundle содержит один выбранный контекст; ссылки `*_ids` внутри него указывают на единственную представленную версию этого ID. Несколько версий одного ID хранятся в архиве, а не одновременно в одном bundle. Точные исторические ссылки используют EntityRef.

Суммы передаются десятичными строками с валютой, чтобы не терять точность. Бюджет продукта находится в BriefInput; бюджет API — в Limits. Они независимы. Стоимости разных валют нельзя складывать без отдельного зафиксированного курса. При неизвестной стоимости Usage.cost = null и cost_basis = unknown; неизвестное использование не равно нулю.

Даты — ISO 8601 с часовым поясом; сервер сохраняет UTC. Неизвестная дата публикации = null. Пользовательские сведения не превращаются автоматически в external_fact. Для недоступного источника content_excerpt и locator могут быть null; он не подтверждает факт.

3. **Граница ответственности агента и платформы.**

Платформа передаёт StageRequest с релевантным контекстом. Участник 2 возвращает StageResult. Артефакт содержит ссылки, данные объектов находятся в DataBundle. Платформа валидирует и сохраняет их совместно. У агентов нет прямой записи в таблицы запусков и права самостоятельно менять статусы.

`success` — этап выполнен; `needs_input` — нужны вопросы пользователю; `needs_revision` — требуется доработка; `incomplete` — получен частичный результат; `failed` — выполнение сорвалось. Для failed обязательна ошибка, для needs_input — хотя бы один вопрос. suggested_next_stage является рекомендацией, допустимый переход выбирает оркестратор.

Этапы: brief → research → options → communications → review → selection → report. Из review разрешён возврат к research/options/communications по замечаниям. Из selection можно запросить новую доработку. Лимит циклов задаёт платформа. Исправление брифа может вернуть процесс к brief.

Usage создаётся адаптером/инструментом. Агент возвращает только usage_ids уже зарегистрированных событий. Повторная передача StageResult не должна повторно увеличивать расходы. Для нового вызова после сбоя используется новый call_id; повтор записи одного события сохраняет прежний id.

4. **Переходы состояния запуска.**

| Из состояния | Разрешённые следующие состояния |
|---|---|
| queued | running, paused, failed |
| running | pause_requested, waiting_for_input, completed, incomplete, failed |
| pause_requested | paused, waiting_for_input, completed, incomplete, failed |
| paused | queued |
| waiting_for_input | queued, paused |
| failed | queued при retryable=true |
| incomplete | queued после решения пользователя/изменения условий |
| completed | Нет перехода; новая работа создаёт новый Run |

Пауза выполняется на безопасной границе этапа. Если последний этап успел завершиться, запрос паузы может закончиться completed. Запрос паузы в paused идемпотентен. После аварийного перезапуска зависший running/pause_requested переводится в paused с сохранением последней подтверждённой контрольной точки; незавершённый внешний вызов может повториться.

Качество независимо от технического статуса: draft — ещё готовится; blocked — есть неустранённые блокирующие замечания; ready — проверки завершены и блокирующих замечаний нет. Ready не означает доказанную рыночную эффективность. Открытые гипотезы остаются помеченными.

5. **Версии, правки и актуальность.**

BriefVersion неизменяем. Правка создаёт version + 1 с полной заменой BriefInput. При running, queued или pause_requested правка возвращает 409 INVALID_STATE: сначала требуется безопасная остановка. Для paused/waiting_for_input/failed/incomplete текущий запуск получает новый brief_version, revision увеличивается; проект остаётся paused до явного продолжения. Старые решения и артефакты сохраняются как история. Для completed новый бриф используется в новом запуске.

Run.revision увеличивается при каждом сохранённом изменении состояния. Управляющие команды передают expected_revision; конфликт возвращает 409 VERSION_CONFLICT. Правка брифа аналогично использует expected_brief_version. GET snapshot отдаёт согласованную ревизию, а не смесь результатов параллельных чтений.

Начальное правило пересчёта: изменение продукта, цели, аудитории, горизонта, бюджета, ограничений или исключённых источников помечает все результаты после brief устаревшими. Это консервативная безопасная основа. Более точную карту повторного использования участник 2 подготовит в B7.

В Snapshot.artifacts могут присутствовать метаданные старых stale-артефактов рядом с актуальными current-результатами. Исторические EntityRef разрешаются через архив платформы; их версии не обязаны присутствовать в текущем DataBundle. Полные старые сообщения, замечания и прочие сущности получают из архивного контекста отдельно. Проверка снимка не подтверждает существование содержимого внешнего архива; это проверка хранилища A4.

Для current-артефактов все EntityRef обязаны разрешаться в DataBundle с точной версией, и они могут зависеть только от current-артефактов текущего брифа. Метаданные всех перечисленных зависимостей должны присутствовать в Snapshot.artifacts; циклы запрещены, в том числе в истории. Для quality=ready необходим current-артефакт этапа report и DataBundle текущей версии брифа. Наличие stale-истории само по себе готовность не блокирует. До пересчёта, при draft/blocked, bundle может показывать старый контекст, но он не становится готовым отчётом. Простая смена stale на current запрещена: требуется повторная проверка/создание новой версии.

Выбор опции допустим в waiting_for_input на этапе selection и относится к текущим option_id + option_version. Ответы принимаются только для ожидаемых question_id; обязательные вопросы должны быть заполнены. Исключение источника допустимо в остановленном запуске, создаёт новый BriefVersion с дополненным excluded_source_ids и запускает обычное инвалидирование; ответ содержит новую ревизию Run.

6. **API для интерфейса.**

Префикс `/api/v1`; точные тела запросов/ответов — в `openapi.json`.

| Операция | Маршрут |
|---|---|
| Создать/перечислить проекты | POST / GET `/projects` |
| Получить бриф / создать новую версию | GET `/projects/{project_id}/brief`, POST `/projects/{project_id}/brief-versions` |
| Создать/перечислить запуски | POST / GET `/projects/{project_id}/runs` |
| Получить статус / полный снимок | GET `/runs/{run_id}`, GET `/runs/{run_id}/snapshot` |
| Получить метаданные результатов / использование | GET `/runs/{run_id}/artifacts`, GET `/runs/{run_id}/usage` |
| Пауза / продолжение | POST `/runs/{run_id}/pause`, POST `/runs/{run_id}/resume` |
| Ответить / выбрать вариант | POST `/runs/{run_id}/answers`, POST `/runs/{run_id}/selection` |
| Исключить источник | POST `/runs/{run_id}/exclude-source` |
| Создать / скачать выгрузку | POST `/projects/{project_id}/exports`, GET `/exports/{export_id}/download` |

Каждая POST-команда требует Idempotency-Key. Ключ уникален в пределах маршрута и его path-параметров: тот же ключ и то же тело возвращают исходный успешный ответ, другое тело — 409. Проверка ключа выполняется до проверки expected_revision, чтобы безопасно повторить потерянный ответ. Неуспешные команды откатываются и не резервируют ключ. Для первой локальной версии ключи сохраняются в базе без автоматического срока удаления; удаление проектов пока не реализовано.

202 означает, что команда принята; состояние отслеживается через GET. POST createRun допускает только актуальную версию брифа и не создаёт второй незавершённый запуск для того же проекта. На установке только один running/pause_requested; очередью управляет worker. Новый запуск после завершённого/failed/incomplete сохраняет прежний как историю.

POST resume допускается для paused, для retryable failed и для incomplete после решения о продолжении; waiting_for_input продолжается через answers или selection. Повтор same-key безопасен. Выбор и ответы возвращают queued. Несуществующий ID — 404; неверный формат — 422; конфликт версии/состояния — 409; временная недоступность API — 503. Ошибка внешнего сервиса внутри принятого запуска сохраняется в Run.error и доступна через GET с HTTP 200.

Экспорт синхронный по контракту: 201 возвращает Export и download_url. Только текущая ревизия, без stale-артефактов. allow_draft=false требует quality=ready; true разрешает явно помеченный черновик/blocked-документ. Исторический уже созданный экспорт сохраняет свою версию; его не следует показывать как актуальный.

7. **Проверки, которые нельзя выразить одним JSON Schema.**

- Связанные объекты принадлежат одному проекту, все ID и версии существуют.
- Каждый EntityRef текущего артефакта разрешается в DataBundle; исторические EntityRef — в архиве платформы. Artifact.depends_on разрешается в метаданные снимка; циклы зависимостей запрещены.
- Для external_fact со статусом supported требуется поддерживающий фрагмент прочитанного источника; противоречия не игнорируются.
- Allowed-сообщение не обещает planned/hypothesis-возможность как доступную. Семантическое соответствие проверяет критик.
- Ready требует текущий report и текущий DataBundle. Stale-история разрешена; blocked-сообщения и неустранённые blocking-замечания текущего контекста запрещены.
- Блокирующее замечание нельзя обходить статусом accepted_limitation: сначала убрать неподтверждённое утверждение/обещание или оставить качество blocked.

Схема проверяет формат. Ссылочную целостность проверяет платформа; смысл и поддержку утверждений — проверки участника 2 и независимая приёмка участника 3.

8. **Примеры и приёмка A1.**

`success` — полный условный результат; `needs_input` — вопрос о бюджете; `conflicting_sources` — спорные сведения; `unsupported_promise` — обещание запланированной функции; `search_error` — сбой внешнего сервиса; `stale_result` — новая версия брифа со старым результатом. Отдельно даны вход/выход этапа и ошибка API. usage=[] в примерах означает отсутствие реальных вызовов, а не бесплатную работу модели.

Проверка: `python3 scripts/check_contracts.py`. Нужна библиотека `jsonschema`; полный стек приложения для этой проверки не требуется.
