Передача платформы участникам 2 и 3

Состояние на 12 ноября 2026. Текущая база платформы: A9, `83fdea8`; A10 добавляет экспорт измерений и материалы сдачи. Локальная LizaLiza: `8731ec7`, база ответвления `9736534`. Обновление origin не удалось: GitHub требует авторизацию. Поэтому локальная копия не объявляется актуальной удалённой версией. Ветки участника 3 среди доступных локальных ссылок нет.

**Порядок соединения.**

1. После настройки доступа выполнить `git fetch origin` и проверить актуальные SHA веток. Fetch обновляет сведения и не объединяет ветки. Зафиксировать версии компонентов перед приёмкой.
2. Для агентов закрыть воспроизводимые дефекты ревью и подключить контроль A7–A9. Проверять небольшую интеграционную ветку от актуальной платформы; не переносить старые config.py, README или инфраструктурные файлы целиком поверх новой версии.
3. Прогнать контракты, тесты платформы и реальных обработчиков с подменёнными сервисами. Затем выполнить разрешённый живой сценарий с явно выбранной моделью и фиксированными лимитами, сохранить Usage и измерения.
4. Подключить интерфейс участника 3 к HTTP API и его renderer к интерфейсу `(snapshot, format) -> str`. Повторить C8/C9 на независимых кейсах и оформить подтверждение владельцев компонентов.
5. Из принятого коммита выполнить чистую установку и демонстрацию, собрать материалы и проверить права на ссылки. Публикация и отправка не выполняются автоматически.

Фактическая фабрика в локальной ветке — `app.agents:build_stages`. Пример `app.agents.registry:build_stages` в инструкции платформы обозначает возможный интерфейс, но такого модуля в `8731ec7` нет.

|---|---|
| Учёт и лимиты | Убрать дублирующий CallGate/agent-limits.sqlite3 в пользу A8. Модель вызывает штатный адаптер в контексте worker; инструменты — context.tool_call. Транспорт делает ровно одну попытку и не пишет второй Usage |

| Версии и повторное использование | Явные зависимости StageSpec по B7, версии промптов и модели; неопределённые зависимости означают полный пересчёт |
| Ошибки исследования | Согласовать обновление доказательств ReviewIssue при повторном чтении: сохранилась ли цитата; не подменять старую версию новой без проверки |
| Уточнения | В отчёте отражать действующие ответы с происхождением; не угадывать структуру свободного ответа и не менять исторический бриф на месте |
| Извлечение URL | Проверить многострочный бриф и границы ссылок |
| Покрытие исследования | Второй вопрос должен получить прочитанные материалы либо явный пробел; наличие search-результата не означает прочитанный источник |
| Выбор альтернатив | Рекомендация и причины отказа должны сохраняться и доходить до критика/отчёта, при этом решение пользователя остаётся платформенным |
| Сравнение C9 | Однократная критика не считается полным циклом исправлений; сравнивать одинаковые входы, уточнения и источники |

Это требования повторной приёмки из локального ревью R1–R7, а не утверждение о текущем состоянии удалённой ветки. Исправления участника 2 могут уже существовать на сервере; без успешного fetch это не проверено.
