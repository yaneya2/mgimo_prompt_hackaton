**Команды для участника 3.**

Из корня репозитория, после установки по README:

```bash
.venv/bin/python -E -m pytest -q
.venv/bin/python -E scripts/check_contracts.py
.venv/bin/python -E -m scripts.check_secrets
docker compose config --quiet
```

Без `--run-live-model` тесты не вызывают реальные модели. Они создают временные каталоги, собственные локальные процессы и свободные порты. Для процессных проверок нужны Linux/macOS, возможность запускать дочерние процессы и слушать localhost. Для проверки контейнера нужны разрешённый доступ к Docker и доступ к реестрам во время сборки:

```bash
docker build -t strategy-backend:a9-check .
docker run --rm --network none strategy-backend:a9-check python -c 'import asyncio, os; from pathlib import Path; from app.main import create_app
async def check():
    assert os.getuid() == 10001 and not Path("/app/.env").exists()
    app = create_app()
    async with app.router.lifespan_context(app):
        assert app.state.storage.list_projects() == []
        paths = app.openapi()["paths"]
        assert "/api/v1/runs/{run_id}/summary" in paths and "/api/v1/runs/{run_id}/events" in paths
    print("PASS")
asyncio.run(check())'
```

**Границы проверки и передача дефектов.**

Проверка секретов распознаёт известные форматы ключей, приватные ключи, буквальный APP_MODEL_API_KEY из окружения/локального `.env` длиной от восьми символов и случайно публикуемые каталоги состояния/SQLite. Она проверяет также индекс и удалённые из текущих файлов секреты в доступной истории. Не сканируются удалённые серверы Git, недостижимые объекты и все игнорируемые локальные данные. Брифы, коммерческие сведения и личные документы нельзя надёжно распознать такими правилами: перед публикацией владелец отдельно проверяет их содержание. Экспорт намеренно содержит данные проекта; он не является средством удаления всех конфиденциальных сведений.

Приёмка реальных агентов, экранов, итогового renderer и сравнение качества/стоимости C8/C9 пока не проведены. Оценочный денежный резерв и кооперативный тайм-аут сохраняют ограничения, описанные в [A8](../../app/workflow/RUNTIME.md). Проверенный локальный образ оставлен для повторного запуска; проверка не пересоздавала рабочие контейнеры и тома.

Для нового дефекта записать: версию кода, ID Run и ревизию, синтетические входы, выполненное действие, ожидаемое и наблюдаемое состояние, владельца компонента, команду воспроизведения. Прикладывать только проверенные обезличенные файлы. Независимый результат участника 3 фиксируется отдельной записью; этот протокол не заменяет его подтверждение.
