# Ревью LizaLiza — 8cd4d12

15 ноября 2026. Проверен локальный origin/LizaLiza; fetch не выполнен из-за отсутствия авторизации GitHub. Ветки не объединялись. Сравнение: текущая master b19e8bd и изменения нового коммита относительно общего предка.

## Замечания

### P2 — В истории пропадают названия событий

app/ui/static/app.js:54. Обновлённый overview выводит x.state, но актуальный API событий возвращает kind и code. Например, завершённый этап представлен kind=step_completed, code=success; поля state нет. После экранирования undefined превращается в пустую строку: пользователь видит этап и время, но не событие. Нужно сохранить обработку kind/code, уже имеющуюся в master. Проверять на фактической структуре /runs/{id}/events.

### P2 — Состояние раскрытых блоков привязано к одинаковому тексту, а не объекту

app/ui/static/app.js:22,31. Открытые details запоминаются по textContent заголовка summary. У всех источников один заголовок «Сохранённый фрагмент»: после обновления данных открытие одного источника откроет остальные. Состояние также переносится между проектами и запусками при совпадении заголовков. Нужен ключ проект/запуск/вкладка/идентификатор объекта. Проверять на нескольких источниках и переходе между проектами, а не только на одной истории запуска.

### P2 — До выбора исчезла явная рекомендация системы

app/ui/static/app.js:58–63. Новая таблица и подробности вариантов показывают свойства отдельных вариантов, но options больше не выводит актуальную сводку артефакта options. Вместе с ней пропадает явное указание рекомендованного направления, причин отклонения альтернатив и условий смены предпочтения. shortReport появляется только после выбора и использует rationale выбранного пользователем варианта; это не замена исходному сравнительному заключению. Нужно вернуть небольшое сравнительное заключение перед таблицей, отдельно от выбора пользователя.

## Риски объединения с master

Это расхождения веток, а не обязательно ошибки, внесённые именно новым коммитом:

- В LizaLiza остаётся timeout_seconds=1800 вместо согласованного отсутствия ограничения времени.
- Нет текущего startCurrent: после изменения брифа отправляется безусловный POST нового запуска. Нельзя терять интеграцию с переиспользованием/продолжением текущего запуска.
- reportView снова выводит сырой сохранённый Markdown: вернутся agent_*, JSON, английские статусы и отсутствие предупреждения об ограничениях источников.
- reviews показывает только issues, без заключения критика, и снова выводит внутренний ID объекта.
- Новый CSS полностью заменяет прежние слои: при переносе нужно проверить оглавление и читаемый отчёт из master.

## Что улучшено

Форма в два шага; более понятный следующий шаг; таблица для сопоставления вариантов; отдельное подтверждение выбора; отсутствие перерисовки при неизменных данных; автоматический переход к актуальному завершённому отчёту без повторного перехвата вкладки; локальный шрифт Manrope с лицензией. Архитектурно report-model.js выделяет чистую логику представления без новых вызовов модели.

## Проверки и ограничения

В изолированной временной директории выполнены оба добавленный/связанный набора Node-проверок: tests/test_report_model.mjs и tests/test_markdown.mjs — прошли. Они проверяют модели представления и Markdown; не проверяют события реального API, уникальность раскрываемых блоков, работу формы с текущим backend и наличие сравнительного заключения до выбора. Полный браузерный прогон ветки в этом ревью не выполнялся.

Вердикт: полезное обновление интерфейса, но требуется исправить три замечания и аккуратно объединить его с текущей логикой master; целиком заменять app.js версией ветки нельзя.
