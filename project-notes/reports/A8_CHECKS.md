Проверка A8: ошибки, лимиты, кэш и наблюдаемость

Дата: 11 ноября 2026. Ветка: `master`, изменения поверх A7 (`8c696f0`). Ветка `LizaLiza` не объединялась; проверена платформенная часть с подменёнными внешними сервисами. Платных запросов в этих проверках нет.

Реализовано:

- SQLite v4 сохраняет резервы каждой внешней попытки, проверенные ответы кэша и события запуска. Миграции v1/v2/v3 сохраняют данные.
- Квоты модели, инструментов и этапов, накопленное активное время, лимит исправлений и денежная оценка не сбрасываются при паузе, восстановлении или правке брифа. Повторы расходуют отдельную квоту; исчерпание лимита сохраняет incomplete и причину остановки.
- Денежные резервы создаются до обращения к сервису. Оплаченная ошибка учитывается до решения о повторе; неизвестная стоимость остаётся неизвестной. Попытка без Usage после аварии удерживает квоту и резерв. Валюты не смешиваются.
- Кэш в пределах Run учитывает входы, версии, модель, промпт, схему и параметры; проверяет срок, целостность и происхождение. Попадание создаёт отдельный Usage с нулевыми новыми расходами и ссылкой cache_origin_id.
- Штатные адаптеры модели автоматически используют контроль worker. context.tool_call предоставляет инструментам единый интерфейс резервирования, ограниченных повторов, кэша и учёта.
- GET `/api/v1/runs/{id}/summary` и `/events` возвращают сводку и события для интерфейса. accounting_complete учитывает также незавершённые резервы. События содержат безопасные коды без промптов, ответов, аргументов, URL и секретов.

В `tests/test_runtime.py` добавлено 26 случаев. Основные сценарии:

| Сценарий | Наблюдаемый результат |
|---|---|
| Два одинаковых запроса при квоте 1 | Один внешний запрос, второй ответ из кэша; исходная цена сохранена, новое использование нулевое |
| Пауза и новое подключение к базе | Проверенный кэш доступен после продолжения; квота не обнуляется |
| Изменение текста, промпта, схемы, модели или версии брифа | Новый запрос; прежний ответ не подставляется |
| Истёкший, отключённый или повреждённый кэш | Ответ не используется; повреждение фиксируется безопасным кодом |
| Оплаченная ошибка модели или инструмента | Usage ошибки сохранён, повтор допускается только при оставшемся резерве/квоте |
| Неизвестная стоимость и денежный лимит | Сохраняется явно заданный резерв; без резерва обращение не начинается |
| Фактическая цена выше резерва | Перерасход виден в учёте, дальнейшая работа останавливается |
| Осталось меньше времени, чем тайм-аут адаптера | Передан и записан оставшийся интервал; поздний ответ/тайм-аут завершает Run по ACTIVE_TIME_LIMIT |
| Resume или правка после исчерпания квоты | Лимит не сбрасывается, новая внешняя попытка не начинается |
| Ожидание человека | Не расходует активное время |
| Временная ошибка поиска | Только разрешённый ограниченный повтор; каждая попытка учтена |
| Невалидный ответ инструмента | Нет автоматического повтора и раскрытия сырого исключения |
| SIGKILL отдельного процесса после резервирования | Новый процесс видит резерв без Usage; accounting_complete=false, повтор сверх квоты запрещён |
| Два одновременных резервирования при квоте 1 | Только один получает разрешение; нет превышения квоты из-за гонки |
| Старое использование с неизвестной ценой или другой валютой | При денежном лимите новые действия блокируются с явной причиной |
| Вызов адаптера с Storage без контекста worker | Внешнее обращение отклоняется до транспорта |

Полный набор также проверяет настоящие процессы API и worker на localhost: сценарии A6/A7 заканчиваются выгрузками, после перезапуска доступны прежние Snapshot, summary, events и неизменные файлы. `scripts.try_api` сохраняет `summary.json` и `events.json` рядом с документами. Прежние проверки остановки, сохранения Usage, идемпотентности команд, ревизий и версий продолжают проходить.

Границы приёмки: денежный резерв — оценка, не ограничение списаний на стороне провайдера. Фактическая цена может превысить резерв; это фиксируется после ответа. Тайм-аут кооперативный: транспорт должен соблюдать переданный предел, произвольный зависший обработчик принудительно не завершается. После аварии неизвестный период до восстановления учитывается в активном времени консервативно. При неизвестной модели по умолчанию кэш модели отключён.

Реальные агенты B1–B6 и транспорт Tavily из LizaLiza ещё не подключены: при интеграции необходимо заменить отдельный CallGate и внутренний учёт/повторы инструментов на context.tool_call, исключив двойное начисление. Независимая приёмка через интерфейс участника 3, живые проверки моделей/поиска и сравнение качества/стоимости ещё предстоят. Новый Docker-образ в этой проверке не собирался.
