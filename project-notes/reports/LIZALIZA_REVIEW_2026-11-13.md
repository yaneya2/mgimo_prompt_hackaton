## Замечания

### R8 — P2: исключение источника перестаёт действовать в новом Run

`app/tools/research.py:47`, `app/agents/runtime.py:117–120`.

ID источника вычисляется из run_id и URL. В брифе запрет хранится как excluded_source_ids, а перед чтением сравнивается с ID, заново рассчитанным для текущего запуска. Новый запуск того же проекта с прежним списком исключений получает другой ID для той же страницы: страница вновь проходит фильтр. Это нарушает ожидаемое действие пользовательского исключения (B3/C4).

Локальное воспроизведение: вызвать source с одинаковым URL https://example.org/evidence для исходного StageRequest и его копии с run_id=run_second; поместить первый ID в excluded_source_ids копии. Проверка нового ID в списке возвращает False. Внешние сервисы не вызывались.

Исправление: разрешать архивные ID исключений в стабильную идентичность материала (канонический URL/ключ файла) на уровне проекта и фильтровать по ней, сохранив неизменяемые архивные ссылки. Проверка: исключить материал, создать новый запуск того же проекта, убедиться, что Extract не получает этот URL.

### R9 — P2: исследовательские HTTP-вызовы обходят управление паузой платформы

`app/tools/research.py:70–96`, `app/agents/limits.py:30–48`.

Search/Extract напрямую выполняют HTTP и учитывают вызов через собственный CallGate. Он проверяет отдельные счётчики и время, но не состояние pause_requested. Если запросить паузу во время первого поискового запроса, следующий search и extract могут начаться до возврата из обработчика. На master для проверки состояния перед каждым новым внешним действием предусмотрены app.tools.control.tool_call и app.execution; исследовательский адаптер их не использует. Это интеграционный дефект относительно A7/A8, а не падение существующего теста ветки.

Исправление: подключить транспорт к единому контроллеру платформы, согласовать резервирование, оставшееся время и единственного владельца Usage. Проверка: запросить паузу после первого поискового ответа и убедиться, что второй внешний вызов не состоялся. Не добавлять повторную регистрацию Usage поверх существующей.

### R10 — P2: любой денежный лимит блокирует агентов независимо от тарификации

`app/agents/limits.py:34–35`.

CallGate.reserve безусловно отклоняет budget != None до первого вызова. Даже при настроенных ставках модели или верхней оценке стоимости платформы агент возвращает incomplete. Поэтому после объединения пользователь сможет пользоваться агентами только с отключённым денежным лимитом. Осторожная остановка при действительно неизвестной цене оправданна; безусловный запрет не использует уже реализованную политику A8.

Исправление: передать денежный контроль платформенному резервированию; сохранить отказ при отсутствии надёжной верхней оценки. Добавить совместный тест с известной ценой, достаточным бюджетом и последующим исчерпанием. Это замечание о совместимости с текущим master; в старой платформе ветки ограничение явно заложено и покрыто тестом.
