## R11 — P1: команда и результат её выполнения сохраняются раздельно

`app/api/business.py:40–51`, `app/storage/controls.py:46–57`.

Commands.execute открывает транзакцию в api.sqlite3, но callback самостоятельно фиксирует изменения в основной базе Storage. При аварии между callback и INSERT commands состояние уже изменено, а подтверждения Idempotency-Key нет. Повтор изменения брифа с тем же ключом получает Conflict вместо первоначального успешного результата. Для выбора и ответов действует та же граница между изменением и сохранением квитанции.

Дополнительно exclude сначала фиксирует новую версию брифа и переводит прежний запуск в incomplete, затем отдельно создаёт новый запуск. Сбой второй операции оставляет пользователя с изменённым брифом без обещанного пересчёта. Повтор прежней команды конфликтует с обновлённой ревизией.

Воспроизведено локально без внешних вызовов:
- После revise внутри callback искусственно выброшен OSError до записи квитанции. Повтор Commands.execute с тем же ключом: Conflict, текущая версия брифа уже 2.
- После синтетического прохода до selection create_run заменён функцией, выбрасывающей OSError. exclude оставил brief v2, старый run incomplete, количество запусков 1.

Исправление: состояние команды, квитанцию и создание нового запуска фиксировать одной транзакцией основной БД. При объединении использовать уже реализованный на master слой команд, а не переносить второй конкурирующий механизм. Добавить проверки сбоя между шагами и повторения команды после рестарта. ## R12 — P2: исключение файла блокирует другие файлы с таким же именем

`app/agents/runtime.py:87–91`, `app/storage/controls.py:60–67`.

Исключённые user_file сопоставляются по source.title, а title создаётся как Path.name. При материалах `product/card.md` и `market/card.md` исключение первого приводит к пропуску обоих. В модели исключения отсутствует уникальный относительный ключ файла, поэтому пользователь теряет и разрешённое свидетельство. Условие непосредственно следует из Path(path).name not in excluded_files.

Исправление: сохранять стабильную идентичность материала относительно корня research_materials_dir и сравнивать по ней. Не раскрывать абсолютные локальные пути в UI. Проверка: два разных файла с одинаковым basename; исключение одного не должно мешать чтению другого.
