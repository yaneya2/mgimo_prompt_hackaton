Переход на сменные модели и локальный Codex

Пользователь выбрал свой установленный Codex с возможностью последующей замены. Выделены общие ModelAdapter/ModelResult/ModelError и валидация, добавлены create_model и CodexAdapter. OpenRouter сохранён как альтернативная реализация. В локальном `.env` изменён только APP_MODEL_PROVIDER на codex, остальные настройки сохранены. Пароли/ключи из авторизации Codex не читались и не копировались.

Проверки:

- Установлен codex-cli 0.165.0; login status подтвердил вход через ChatGPT.
- 45 тестов прошли: прежние 33 плюс 12 проверок Codex, фабрики и управления процессом. Подтверждены переключение провайдера, JSON/Usage, ошибки, тайм-аут, удаление временного каталога и отсутствие секретов в ошибках.
- Все проверки контрактов A1 прошли.
- Первый запуск в песочнице завершился ошибкой CLI. Повтор вне песочницы с разрешением на проверку существующего аккаунта прошёл: data={"answer":"ok"}, событие Usage записано, ID сессии получен.
- model=null отражает отсутствие точного имени выбранной встроенной модели в событиях CLI; стоимость=null/unknown. Это не заявление о бесплатном вызове.

Ограничения: код провайдера Codex выполняется локально под авторизованным пользователем. В Docker нет CLI и его авторизации; для контейнерного доступа к Codex на хосте нужен отдельный транспорт. APP_MODEL_MAX_TOKENS/MAX_RETRIES относятся к OpenRouter, Codex ограничен общим тайм-аутом процесса и не повторяется автоматически. Пользовательский config.toml не загружается; встроенную модель можно заменить явным APP_MODEL_NAME. Проверки валидации не гарантируют достоверность стратегии.
