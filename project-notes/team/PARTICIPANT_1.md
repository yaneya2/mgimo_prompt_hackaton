План участника 1: платформа, выполнение и интеграция

Общий порядок приёмки и распределение: [ROADMAP.md](../ROADMAP.md). Задачи не привязаны к дням. Их номера нужны для зависимостей; начинать независимые части можно параллельно. P0 — первый полный проход, P1 — обязательное доведение до приёмки.

Твой результат: локально запускаемая система с API, которая выполняет этапы агентов, сохраняет результаты, учитывает вызовы, позволяет вмешаться и продолжает проект после перезапуска.

Оформить Pydantic/JSON-схемы, формат результата этапа и ошибки. Вместе подготовить примеры обычного, неполного и ошибочного результатов. Согласовать API создания проекта/запуска, статуса, артефактов, вопросов, паузы, продолжения, правки и выбора.

Зависимости: общая постановка. Готово, когда 2 и 3 используют примеры без преобразований и могут разрабатывать свои части независимо.

Техническая часть реализована: фиксированный граф, отдельный процесс worker, сохранённые уточнения и выбор человека, проверка результатов, ограниченные исправления и маршруты критика, продолжение с контрольной точки. Полный синтетический проход проверен через три процесса worker; аварийное восстановление — через SIGKILL. [Инструкция и подключение функций](../../app/workflow/README.md), [протокол A5](../reports/A5_CHECKS.md). Реальные B1–B6 в репозитории пока отсутствуют: полная приёмка A5 после их подключения и независимая проверка участником 3 ещё впереди.

Сначала соединить тестовые этапы, затем подставить функции участника 2. Реализовать заданный граф: бриф → исследование → варианты → коммуникации → критик → выбор → итог. Обрабатывать вопросы пользователю и структурированные замечания. Worker должен выполнять задачи независимо от перерисовки интерфейса.

Результаты агентов проверять по схеме; невалидный ответ не передавать дальше. Предусмотреть ограниченные исправления и возврат к нужному этапу. При исчерпании лимита завершать с понятным неполным результатом.

Повтор незавершённого внешнего запроса допускается с документированным ограничением.
