Ограничения, кэш и наблюдаемость A8

Worker контролирует каждый вызов штатных адаптеров модели и инструментов, подключённых через `context.tool_call`. Резерв попытки сохраняется в SQLite до обращения к сервису. Завершённая попытка связывается с Usage одной транзакцией. Перезапуск, resume и новая версия брифа того же Run не обнуляют счётчики.

1. **Лимиты запуска.**

| Поле Limits | Действие |
|---|---|
| max_model_calls | Число попыток модели, включая ошибки и повторы |
| max_search_calls | Число попыток управляемых инструментов; Search и Extract считаются отдельно, чтение файла через эту обёртку также занимает попытку |
| max_repair_cycles | Существующий предел исправлений оркестратора |
| timeout_seconds | Активное время всех заданий запуска |
| budget | Отдельный бюджет вызовов API; null отключает денежную проверку |
| max_steps | Необязательное поле, по умолчанию 100; до обработчика проверяется число попыток этапов |
| cache_ttl_seconds | Необязательное поле, по умолчанию 3600, диапазон 0–86400; 0 отключает кэш ответов |

Usage не является единственным счётчиком: зарезервированная попытка без записанного ответа тоже расходует квоту. Это не позволяет повторить потерянный запрос сверх лимита после SIGKILL. Нельзя считать такую попытку бесплатно завершившейся или отменённой.

Время ожидания человека, очереди и обычной паузы не включается. Активное время берётся из записей jobs; после аварии время незавершённого задания до восстановления учитывается консервативно, включая неизвестный период простоя. Перед запросом адаптер получает минимум собственного тайм-аута и оставшегося времени Run. OpenRouter сохраняет тайм-аут транспорта, Codex — процесса. Перед и после обработчика выполняется дополнительная проверка. Это кооперативный предел: произвольный Python-обработчик, который завис внутри себя, принудительно не завершается; инструмент обязан соблюдать переданный timeout. Ответ, пришедший после истечения лимита Run, не запускает следующий этап.

При исчерпании лимита Run становится incomplete с сохранённой контрольной точкой, расходами и диагностикой. `summary.stop_reason` содержит причину: MODEL_CALL_LIMIT, SEARCH_CALL_LIMIT, STEP_LIMIT, ACTIVE_TIME_LIMIT или денежный код. Диагностическое завершение тоже имеет job, поэтому `summary.steps` показывает все попытки заданий, в том числе остановленные до вызова обработчика. Пользовательские контрольные точки правки брифа в счётчик не входят.

Лимиты созданного Run неизменяемы. Resume не добавляет попытки или бюджет. Для работы с другими пределами нужен явный новый Run; прежний остаётся в истории. Ошибка сервиса сама по себе сохраняет проект; повторы ограничены квотой и настройками адаптера/инструмента.

2. **Денежный резерв и точность.**

Перед каждой попыткой модели с непустым Limits.budget требуется `APP_MODEL_CALL_COST_RESERVE`: операторская оценка резерва на одну попытку в `APP_MODEL_COST_CURRENCY`. Для инструмента аналогичная оценка передаётся в `maximum_cost={amount, currency}`. Если её нет, внешнего вызова не происходит: COST_RESERVE_REQUIRED. Значение не выбирается платформой по вымышленному тарифу.

Суммы рассчитываются целыми миллионными долями валюты, без потери точности float. Если сервис сообщил стоимость, она заменяет резерв. При оценочной стоимости сохраняется максимум оценки и резерва; при неизвестной стоимости резерв остаётся занятым. Неучтённая после сбоя попытка также удерживает резерв. Старые неизвестные расходы без резерва дают UNKNOWN_PREVIOUS_COST, несовпадающие валюты — CURRENCY_MISMATCH; автоматической конвертации нет.

Резерв **не ограничивает списание на стороне провайдера**. Если его оценка оказалась ниже фактической цены, перерасход записывается и следующие действия останавливаются. Поэтому `remaining_estimate` — оценка доступного остатка, а не гарантия баланса аккаунта. Для гарантированного ограничения списаний нужен также лимит самого провайдера. Неизвестная стоимость не превращается в ноль. Тарифы APP_MODEL_*_COST_PER_MILLION остаются отдельной послевызовной оценкой по токенам; они не подменяют резерв.

3. **Кэш ответов.**

Кэш находится в SQLite и ограничен одним Run. Ключ включает хеш полного StageRequest (в том числе версии брифа, данных и входных артефактов), сохранённые ответы и выбор из StageContext.inputs, состояние исправлений, этап, провайдера, заданную модель, промпт, схему ответа и параметры генерации. Для инструментов дополнительно учитываются имя, версия, аргументы и схема. Изменение входов, модели, промпта или новой версии брифа вызывает новый запрос. Для неизвестной модели по умолчанию кэш модели отключён.

После исправления A9 используется версия ключа 2. Ответы со старым ключом не подставляются; при следующем обращении возможна новая учтённая попытка. Схема SQLite и история расходов не меняются. Лимит исправлений также сохраняется при правке брифа: изменённый бриф проверяется заново, но уже потраченные автоматические исправления не возвращаются.

Сохраняются только успешные проверенные ответы размером до 1 MiB. Срок хранения для модели ограничен Limits.cache_ttl_seconds, для инструмента — также явным cache_ttl_seconds вызова (по умолчанию 0). Попадание в кэш не продлевает срок. Ответы проверяются по хешу целостности и схеме; повреждённая запись удаляется перед обычной попыткой. Истёкшая запись не используется. Истечение срока не является процедурой удаления всех старых данных проекта.

Попадание создаёт новый Usage с cached=true, cache_origin_id исходной попытки, нулём новых токенов и стоимости. Это нулевая цена **нового внешнего обращения, которого не было**; прежний вызов и его неизвестная/оценочная стоимость остаются в учёте. Квота вызовов и денежный резерв повторно не расходуются. Сводка отдельно показывает cached_events и external_attempts. Повторное использование целого этапа A7 отражается в Artifact.reused_from и событии stage_reused, а не новым Usage.

Кэш содержит локальные результаты, поэтому хранится в том же закрытом APP_DATA_DIR, что и остальные данные. В журнале событий остаются только коды; промпты, ключи, аргументы, ответы и URL туда не записываются. Хеш целостности помогает обнаружить повреждение, но не защищает от человека с правом изменять базу и пересчитать хеш.

4. **Подключение модели и инструментов.**

Штатные OpenRouterAdapter и CodexAdapter автоматически используют контекст worker. Адаптер с Storage/RecordingSink вне этого контекста отклоняет вызов до обращения к сервису; это также предотвращает случайный обход контроля через новый поток. Указанный этап модели должен совпадать с активным этапом worker; несоответствие отклоняется до резервирования и обращения к сервису. Обработчики синхронные. Автономные пробы A3 с JsonlUsageSink остаются отдельными явно запускаемыми проверками, без бюджета конкретного Run и без этого кэша.

Для инструментов использовать один владелец резервирования, повторов и Usage:

```python
result = context.tool_call(
    name='search', provider='research-service', version='search-v1',
    arguments={'query': query, 'max_results': 5},
    schema={'type': 'object', 'required': ['results'],
            'properties': {'results': {'type': 'array'}}},
    invoke=lambda timeout: transport_search(query, timeout=timeout),
    timeout_seconds=20, max_retries=1, cache_ttl_seconds=60,
    maximum_cost=None,  # При Limits.budget нужен обоснованный резерв в его валюте.
)
sources = result.data['results']
usage_ids = result.usage_ids
```

Транспорт выполняет ровно одну попытку и возвращает JSON; не создаёт Usage, не резервирует квоту и не повторяет запрос сам. Он должен ограничить время/размер ответа, проверить протокол сервиса и включить все влияющие на результат настройки в arguments/version. Если сервис действительно сообщил стоимость, можно вернуть `ToolResponse(data, cost=..., cost_basis='reported')`. Оценка помечается estimated. При отсутствии сведений стоимость остаётся unknown.

Для допустимого повтора транспорт выбрасывает `ToolFailure('RATE_LIMITED')` или `ToolFailure('UNAVAILABLE')`. Остальные ошибки, невалидный ответ и тайм-аут автоматически не повторяются. Максимум — три дополнительных попытки; каждый повтор заново проверяет паузу, время, квоту и бюджет. Платные ошибки можно передать как `ToolFailure('UNAVAILABLE', cost=...)`; стоимость записывается до решения о повторе. Не передавать сырой текст исключения/ответ сервиса. PauseRequested и LimitReached не подавлять.

При интеграции LizaLiza необходимо заменить независимый CallGate и внутренние повторы/Usage инструментов этим интерфейсом. Простое оборачивание уже учитывающего расходы ResearchTools двойным учётом недопустимо. Новый адаптер модели тоже обязан использовать резерв перед каждой попыткой; в качестве образца доступны штатные реализации. Конкретный транспорт Tavily в этой ветке ещё не объединён.

5. **Сводка и события для участника 3.**

- `GET /api/v1/runs/{id}/summary`: статус, лимиты, число попыток модели/инструментов/этапов, активное и оставшееся время, суммы расходов по валютам и основанию оценки, ошибки, повторы, кэш, причина остановки и оценка остатка бюджета.
- `GET /api/v1/runs/{id}/events`: сохранённая последовательность безопасных событий со стадией, временем, kind и code: резерв, Usage, кэш, переход состояния, выполнение/прерывание, восстановление и причина остановки.
- `GET /api/v1/runs/{id}/usage`: прежний полный список событий использования для детализации.

`accounting_complete=false` означает неизвестную стоимость или попытки без записи Usage. `budget.unrecorded_attempts` показывает число таких попыток; при денежном лимите их резервы удерживаются. `usage.totals.cost_complete` относится только к уже записанным Usage, поэтому для общей полноты смотреть именно accounting_complete. Расходы разных валют показаны раздельно.

Сводка и события могут изменяться внутри этапа без новой Run.revision: их следует опрашивать во время running. HTTP access log отключён, чтобы не записывать произвольные query-параметры; транспортные журналы httpx/httpcore в worker ограничены WARNING. Код сторонних обработчиков также обязан соблюдать правило не писать секреты и входные данные в логи.

`scripts.try_api` сохраняет `summary.json` и `events.json` рядом со снимком и выгрузками. Проверки: [протокол A8](../../project-notes/reports/A8_CHECKS.md). SQLite автоматически мигрирует с v1/v2/v3 на v4 без сброса истории. Синтетические проверки не являются живой приёмкой моделей/поиска или оценкой качества стратегии.
