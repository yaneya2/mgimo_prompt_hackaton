HTTP API A6

Реализованы все 17 операций [OpenAPI](../../contracts/openapi.json) с префиксом `/api/v1`. Форматы запросов проверяются по общему [JSON Schema](../../contracts/schema.json); отдельной копии моделей API нет. `/docs` использует встроенные схемы без внешних `$ref`. Прогресс доступен опросом `GET /runs/{run_id}` и `GET /runs/{run_id}/snapshot`.

API сохраняет команды в SQLite. Этапы выполняет отдельный worker с тем же `APP_DATA_DIR`; перезагрузка страницы не останавливает его. В этой ветке доступны синтетические этапы `demo`. Код реальных агентов из `LizaLiza` ещё не объединён.

1. **Повторяемый сценарий для участника 3.**

После установки зависимостей из корневого README запустить в двух терминалах:

```bash
.venv/bin/python -E -m app
```

```bash
.venv/bin/python -E -m app.worker --stages demo
```

В третьем терминале:

```bash
.venv/bin/python -E -m scripts.try_api
```

Скрипт использует только HTTP, без импорта хранилища или workflow. Он создаёт тестовый проект, дважды отправляет одну команду запуска, ждёт уточнения, имитирует ответ и выбор человека, получает завершённый черновик и скачивает Markdown/HTML. Снимок и документы сохраняются в `data/api-checks/<run_id>/`. Каждый вызов создаёт отдельный проект. Для другого адреса есть `--base-url http://127.0.0.1:8001`, для каталога — `--output-dir`.

Синтетический сценарий не вызывает модель или поиск и не подтверждает качество стратегии. Выбор первого варианта выполняется только этим тестовым скриптом; рабочий API требует явной команды человека.

2. **Порядок запросов интерфейса.**

- `POST /projects` принимает `{name, brief}` и возвращает Project.
- `POST /projects/{id}/runs` принимает `{brief_version, limits}` и возвращает Run со статусом queued.
- Опрос Snapshot даёт текущий Run, бриф, артефакты, данные, вопросы и Usage. Для лёгкого опроса достаточно Run; Snapshot перечитывать после изменения `revision`.
- В `waiting_for_input` на обычном этапе передать `{expected_revision, answers: [{question_id, value}]}` в `/runs/{id}/answers`. На selection передать `{expected_revision, option_id, option_version, rationale}` в `/runs/{id}/selection`.
- Для выгрузки передать `{run_id, expected_revision, format, allow_draft}` в `/projects/{id}/exports`; скачать ответ по `download_url`. Форматы: `markdown`, `html`.

Точные обязательные поля BriefInput и Limits находятся в Swagger и контракте. Все POST требуют `Content-Type: application/json` и непустой `Idempotency-Key`.

Один пользовательский жест получает один ключ. При тайм-ауте или потере ответа повторять тот же URL, ключ и тело; новая осознанная команда получает новый ключ. Успешный результат сохраняется вместе с эффектами команды в одной транзакции. Повтор возвращает исходный ответ даже после изменения ревизии, поэтому актуальное состояние нужно читать отдельным GET. Другой JSON с тем же ключом возвращает 409. Неуспешные команды откатываются и ключ не занимают. Порядок ключей JSON не влияет на повтор; порядок элементов массивов влияет.

Запуск для проекта с незавершённым Run отклоняется и с другим ключом. Разные проекты могут стоять в очереди; на установке работает один исполнитель. Ключи и выгрузки сохраняются в базе без автоматического срока удаления.

3. **Пауза и правки.**

`pause` и `resume` принимают `{expected_revision}`. Для queued/waiting_for_input пауза сразу даёт paused. Для running — pause_requested: уже начатый внешний запрос может завершиться, перед следующим действием срабатывает проверка A7. Незавершённый этап останавливается с сохранением прежней контрольной точки и Usage; готовый результат этапа сохраняется. Если этап закончил весь запуск или запросил ввод, сохраняется соответствующий completed/waiting_for_input. После паузы на вопросе resume восстанавливает ожидаемые вопросы без нового вызова агента.

Resume разрешён для paused, retryable failed и incomplete после явного решения пользователя. Он не обнуляет лимит исправлений. Неактуальный исторический бриф не возобновляется. Продолжение без изменения условий может снова закончиться incomplete.

`POST /projects/{id}/brief-versions` принимает `{expected_brief_version, brief}`. Нельзя менять бриф при queued/running/pause_requested: сначала остановить запуск. Последний незавершённый Run получает новую версию брифа и paused/brief; его прежние артефакты становятся stale, текущие данные очищаются, история и расходы сохраняются. Пересчёт начинается после resume. Ответы предыдущей версии брифа в новый контекст не передаются. Повторно созданные сущности с прежними ID получают следующие архивные версии вместе с точными ссылками на них.

Завершённый Run остаётся историческим: правка брифа создаёт условия для нового Run. `exclude-source` принимает `{expected_revision, source_id, source_version, reason}`; в остановленном последнем Run создаёт новую версию брифа с исключённым источником и такой же пересчёт. Устаревшая версия источника отклоняется.

В A7 добавлено выборочное повторное использование по B7: подходящие подтверждённые результаты получают новые версии с `Artifact.reused_from`, остальные этапы выполняются заново. Без декларации зависимостей применяется полный пересчёт. Уже начатый внешний вызов не отменяется; незавершённый этап может повторить вызовы при resume. [Правила, ограничения и подключение инструментов](../workflow/INTERVENTION.md).

4. **Ошибки и выгрузки.**

Все ошибки маршрутов имеют ErrorResponse: 404 — объект отсутствует, 409 — версия/состояние/повтор команды, 422 — запрос не соответствует контракту, 500 — внутренняя ошибка, 503 — временная ошибка хранилища. Сообщения не включают исходные исключения и значения пользовательского ввода. Ошибка выполнения агента сохраняется в `Run.error`; чтение существующего Run по GET остаётся HTTP 200.

Повторные ключи JSON, NaN/Infinity и неизвестные поля отклоняются. Размер тела ограничен `APP_API_MAX_REQUEST_BYTES` (по умолчанию 1 MiB, настройка 1 KiB–10 MiB).

Выгрузка синхронная и привязана к точной ревизии Run. `allow_draft=false` требует ready; true разрешает помеченный черновик/blocked. В renderer передаются только current-артефакты текущего брифа и связанные объекты, включая замечания. Исторические stale-артефакты не попадают в новый документ. Уже сохранённый документ неизменяем и остаётся доступен после правок и перезапуска.

Интерфейс C6: `create_app(settings, renderer=render)`; `render(snapshot: dict, format: str) -> str`. Snapshot проверен по схеме и связям, format — markdown/html. Renderer должен быть локальной функцией без внешних вызовов и побочных эффектов: он работает внутри транзакции выгрузки. Он отвечает за оформление, обозначение `run.quality` и безопасное отображение текста; платформа сохраняет UTF-8 и отдаёт attachment с nosniff/CSP. Ошибка renderer откатывает выгрузку и запись ключа.

Встроенный резервный renderer выводит статус качества, резюме этапов и полные структурированные данные. HTML экранирует содержимое и показывает его в `<pre>`. Это рабочий способ проверить выгрузку до подключения итогового отчёта C6, а не завершённое оформление отчёта.
