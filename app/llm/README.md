Сменные провайдеры модели

Агенты используют `create_model(settings, sink)` и интерфейс `ModelAdapter.generate(...)`. Доступны провайдеры `codex` (локальный Codex CLI с существующим входом) и `openrouter` (HTTP API). Общие ModelResult, ModelError, проверка входа и JSON находятся в `base.py`; выбор реализации — в `factory.py`.

1. **Использование своего Codex.**

Запускать Python-приложение локально под пользователем, у которого установлен и авторизован Codex. Проверить `codex --version` и `codex login status`. При необходимости выполнить `codex login` самостоятельно.

Настройки `.env`:

```dotenv
APP_MODEL_PROVIDER=codex
APP_MODEL_NAME=
APP_CODEX_COMMAND=codex
APP_MODEL_TIMEOUT_SECONDS=60
```

Пустое APP_MODEL_NAME выбирает встроенную модель по умолчанию Codex. При необходимости указать точное имя доступной модели; оно передаётся через `--model`. Для повторяемости исследования рекомендуется зафиксировать имя. Используется существующая авторизация Codex, APP_MODEL_API_KEY для этого провайдера не нужен. Это локальная программа, а не обязательно локальная нейросеть: запросы модели используют доступ и ограничения аккаунта Codex.

Приложение не читает и не копирует файл авторизации. Каждый вызов создаёт отдельный временный каталог, отправляет сообщения через stdin и запускает `codex exec` без shell-интерполяции. Передаются `--json`, `--output-schema`, `--output-last-message`, `--ephemeral`, sandbox read-only; команды оболочки, hooks, apps и веб-поиск отключены. Пользовательский config.toml не загружается (`--ignore-user-config`), чтобы работа не зависела от персональных MCP/хуков; поэтому и заданная там модель не наследуется. Глобальные инструкции/управляемые настройки самого CLI всё ещё могут влиять на ответ. Входные роли передаются внутри одного задания CLI, а не как самостоятельные системные сообщения API.

Проверочный настоящий вызов:

```bash
.venv/bin/python -E -m scripts.try_model
```

Два живых теста генерации (слоган и три вопроса для интервью):

```bash
.venv/bin/python -E -m pytest tests/test_model_live.py --run-live-model -q -s
```

Они используют текущий провайдер из `.env`, требуют его рабочего доступа и расходуют лимиты/баланс. Без `--run-live-model` оба теста пропускаются, в том числе при обычном запуске pytest. Ответы и события использования сохраняются в APP_DATA_DIR/model-checks (по умолчанию `data/model-checks/`, исключено из Git); `-s` показывает генерации в терминале. Ошибка доступа делает тест неуспешным, а не пропущенным. Проверяются JSON, заполненность, язык, число/различие вопросов и запись использования; содержательное качество интервью и достоверность обещаний требуют просмотра человеком. Статус generated в файле означает получение ответа, окончательный статус проверки показывает pytest.

Результат проверяется локально по той же JSON Schema, что и у OpenRouter. Код возврата CLI должен быть 0, последнее терминальное событие — turn.completed, итоговый файл должен содержать корректный JSON. Промежуточное событие error при переподключении не отменяет последующий успешный исход; turn.failed, отсутствие завершения или ненулевой код возврата остаются ошибкой. На тайм-ауте завершается группа локального процесса (POSIX); уже начавшийся удалённый запрос может продолжать расходовать лимиты. Повторов для Codex нет.

Токены берутся из turn.completed. Если CLI не сообщает выбранную модель, при пустом APP_MODEL_NAME возвращается model=null. Денежная стоимость — null/unknown: приложение не приравнивает доступ через подписку к бесплатному вызову. APP_MODEL_MAX_TOKENS и APP_MODEL_MAX_RETRIES применяются только к OpenRouter; Codex CLI не предоставляет через этот адаптер эквивалентного ограничения выходных токенов. Общий timeout действует на весь процесс Codex.

Текущий Docker-образ не содержит Codex и пользовательскую авторизацию. Для режима codex используйте локальный запуск `.venv/bin/python -E -m app`; при занятом порте сначала остановите `docker compose down`, сохранив том. Вызов Codex внутри текущего контейнера вернёт понятную ошибку конфигурации. Подключение к Codex на хосте из контейнера потребует отдельного транспорта; Docker-режим OpenRouter уже поддерживается.

2. **Общий вызов для участника 2.**

```python
from app.config import Settings
from app.llm import create_model, JsonlUsageSink, ModelError

settings = Settings()
sink = JsonlUsageSink(settings.data_dir / "usage.jsonl")
with create_model(settings, sink) as model:
    result = model.generate(
        messages=[{"role": "user", "content": "Предложи вопрос об аудитории продукта."}],
        schema={
            "type": "object",
            "properties": {"answer": {"type": "string"}},
            "required": ["answer"],
            "additionalProperties": False,
        },
        run_id="run_example",
        stage="brief",
    )
    # result.data: проверенный объект
    # result.model: имя модели или None
    # result.generation_id: ID генерации OpenRouter / сессии Codex
    # result.usage_ids: уже записанные события
```

Этот пример — автономная проба с JsonlUsageSink. В рабочем графе фабрика получает RecordingSink, и оба синхронных адаптера вызываются в контексте worker: A8 автоматически резервирует попытку, ограничивает её время и проверяет кэш. Вызов с долговечным sink вне контекста worker (в том числе из произвольного дочернего потока) отклоняется. [Лимиты, стоимость и кэш A8](../workflow/RUNTIME.md).

Runtime-валидация проверяет структуру, но не истинность ответа. Переполнение JSON-чисел (например, 1e309), NaN и Infinity отклоняются. Проверка ссылок различает ключевые слова схемы и обычные имена полей/данные в default, examples, enum и const. Ссылки на удалённые схемы остаются запрещены; локальные JSON Pointer поддерживают экранирование и percent encoding. Не начислять Usage второй раз на основе результата агента. Автономный JSONL хранит события без ключей и входных сообщений; рабочий Run использует транзакционное хранилище SQLite.

3. **Замена провайдера или модели.**

Для другой доступной модели Codex измените APP_MODEL_NAME. Для перехода на OpenRouter измените конфигурацию:

```dotenv
APP_MODEL_PROVIDER=openrouter
APP_MODEL_NAME=точный_id_модели
APP_MODEL_API_KEY=ключ_в_локальном_env
```

Код агентов остаётся тем же. Для запуска с обновлёнными настройками перезапустите локальный процесс или пересоздайте контейнер. Подробности OpenRouter, ошибок и точности расходов: [OPENROUTER.md](OPENROUTER.md).

Новый провайдер реализует ModelAdapter (generate, close и контекстный менеджер), возвращает ModelResult/ModelError и пишет Usage через общий sink. Затем добавляется одна ветка в create_model и проверки адаптера. Несовместимые возможности должны давать явную ошибку, а не переключать модель незаметно.

Основание интеграции: [официальная документация Codex: неинтерактивный запуск](https://learn.chatgpt.com/docs/non-interactive-mode), [настройки инструментов](https://learn.chatgpt.com/docs/config-file/config-reference); дополнительно проверена справка установленного CLI 0.165.0.
