# Интерфейс и управление

После установки по README: `python -E -m scripts.run_local`. Открыть http://127.0.0.1:8000. Сервер и worker работают отдельными процессами; завершение команды останавливает оба. Для учебного показа без модели и поиска: `python -E -m scripts.run_local --demo --data-dir data/demo`.

## Пользовательский путь

1. Создать проект: продукт, работающие функции, цель, аудитории, бюджет, горизонт, ограничения, допущения и пробелы.
2. Дождаться этапов или ответить на уточняющие вопросы. Статус, история событий, вызовы и неизвестная стоимость видны в обзоре.
3. Сравнить направления, открыть основания утверждений и цитаты источников, прочитать замечания критика. Поисковый сниппет не считается прочитанной страницей.
4. Явно выбрать направление с обоснованием. Автоматического решения за пользователя нет.
5. Открыть итог, выгрузить Markdown или HTML. Для черновика требуется отдельное согласие; выгрузка хранит точную ревизию и не меняется при следующих запусках.
6. Изменить бюджет или запреты: во время работы сначала запросить паузу и дождаться завершения текущего этапа. Новая версия запускается полностью, без смешивания прежних рекомендаций с новыми условиями. История остаётся доступной и помечается устаревшей.

Можно исключить источник с указанием причины: создаются новая версия и запуск; URL/имя исключённого материала передаются как запрет, без его прежнего текста. Для обновлённой страницы с другим URL автоматическое распознавание тождественности не гарантируется.

## Архитектура

Браузер (HTML/CSS/JS, без сборщика) → клиент `/api/v1` → FastAPI → SQLite → отдельный worker → существующие агенты и инструменты. Клиент не импортирует backend и не запускает модель. Новые зависимости приложения не добавлены. Контракты JSON Schema переиспользуются сервером; 17 запланированных маршрутов реализованы, дополнительные read-only маршруты дают события, стоимость, возможности и учебные примеры.

Команды требуют Idempotency-Key и сохраняют ответ для повторов. Ревизии и версии проверяются сервером. Пауза не меняет ревизию исполняемого задания до его подтверждения. История checkpoint неизменяема; проекция старой версии помечается stale. Выгрузки Markdown/HTML детерминированы, текст HTML экранируется, внешние ссылки допускают только HTTP(S), скачивание имеет CSP sandbox. Приложение предназначено для локального использования; общей авторизации и многопользовательской изоляции нет.

## Приёмка

`tests/test_interface_api.py`: HTTP → worker → выбор → итог → неизменяемая выгрузка после повторного открытия приложения; повтор команды; устаревшая ревизия; запрет чужого Origin/Host; изменение бюджета и запрет рекламы; история; исключение источника; пауза во время выполняющегося этапа; безопасный HTML.

Браузером проверены создание проекта, выбор с обоснованием, восстановление после обновления страницы и скачивание HTML. Кадры `docs/screenshots` относятся к явно синтетическому сценарию. Полные тесты также проверяют восстановление после SIGKILL в отдельном процессе, неполные данные, сбои поиска, противоречия и внедрение инструкций в источники. Это техническая проверка, а не независимая оценка полезности стратегии.

## Отображение отчёта

Вкладка «Отчёт» отображает сохранённый Markdown как документ: заголовки, маркированные и нумерованные списки, вложенные пункты, выделение, цитаты, код, таблицы и HTTP(S)-ссылки. Содержимое не исполняет исходный HTML и не загружает внешние изображения. Обычный текст остаётся обычным текстом. Идентификаторы с подчёркиваниями сохраняются. Новых сетевых зависимостей и CDN нет.

Проверки renderer при установленном Node.js: `node --test tests/test_markdown.mjs`.

## Упрощение интерфейса, 14 ноября 2026

Новый проект заполняется в два шага: продукт и цель, затем ресурсы и ограничения. Дополнительные допущения скрыты в раскрываемом разделе; переход назад сохраняет данные. На обзоре проекта показывается один следующий шаг в зависимости от статуса. История, управление паузой и метрики сервисов находятся в «История и подробности анализа». На основном уровне остаются обзор, варианты и отчёт; источники и проверка доступны отдельным меню.

Вариант сначала выбирается в сравнении, затем подтверждается вместе с объяснением. После подтверждения открывается обзор со статусом отчёта. Автоматический опрос не перерисовывает неизменившиеся данные и сохраняет раскрытые разделы.

Типографика: локальный Manrope с кириллицей и открытой лицензией в app/ui/static/fonts/OFL.txt. Подключения к CDN нет. Кнопки имеют единый радиус 10 px, карточки 16 px, текст кнопок центрирован. Предыдущие слои CSS заменены одной таблицей стилей.

Браузером проверены: форма и возврат назад, запуск учебного проекта, выбор и подтверждение стратегии, сборка отчёта, сохранение раскрытой истории при опросе, кнопки и узкий экран 390 px без горизонтального переполнения. Текущие кадры: docs/screenshots/ux-*-v3.jpg.

## От результата к действию

Завершённый актуальный запуск с сохранённым отчётом открывает сразу вкладку отчёта. При завершении в открытом окне переход происходит один раз, с прокруткой к началу отчёта. Дальнейший опрос не сбивает вручную выбранный раздел. Исторические и незавершённые результаты автоматически не открываются.

В начале отчёта показывается резюме выбранной человеком стратегии: ценность, основание, первый сохранённый риск и до трёх начальных действий. Действия берутся из методов экспериментов и продуктовых приоритетов; при коротком плане может использоваться сохранённый критерий решения с его основанием. Новая модель для резюме не вызывается; недостающие данные явно отмечаются. Полный отчёт и выгрузки остаются доступны ниже. Резюме является представлением сохранённых данных в интерфейсе; исходные артефакты и скачиваемый Markdown не переписываются.

Варианты сравниваются в общей таблице по аудитории, ценности, ресурсам, рискам и первому эксперименту. Неуказанный эксперимент помечается явно. Выбор выполняется в столбце варианта, затем подтверждается с объяснением. Подробные основания и остальные эксперименты раскрываются ниже. На узком экране прокручивается сама таблица, названия критериев закреплены.

Проверки логики: `node --test tests/test_report_model.mjs tests/test_markdown.mjs` (11 тестов). Браузером подтверждены выбор → автопереход к отчёту, повторное открытие завершённого проекта и сохранение вручную выбранной вкладки при опросе. При ширине 390 px ширина документа 390 px; таблица 780 px прокручивается внутри области 352 px.
