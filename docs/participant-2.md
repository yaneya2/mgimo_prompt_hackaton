## Подключение к платформе

Фабрика: `APP_STAGE_FACTORY=app.agents:build_stages`. Совместима с A1/A5 без изменения JSON-контрактов. Предоставляет brief, research, options, communications, review, report; selection остаётся за платформой. Все записи выполняет worker. API A6 и UI остаются ответственностью участников 1 и 3.

```bash
.bootstrap/bin/uv sync --locked
cp -n .env.example .env
# В .env: APP_STAGE_FACTORY=app.agents:build_stages
# APP_TAVILY_API_KEY=свой_ключ
# Модель: существующий Codex либо настроенный OpenRouter из инструкции A3.
.venv/bin/python -E -m app.workflow create --name "Пилот" --brief examples/agents/tutor.json --limits examples/agents/limits.json
.venv/bin/python -E -m app.worker --stages app.agents:build_stages --once
```

Команды статуса, ответов, выбора и продолжения находятся в app/workflow/README.md. Worker не отвечает за человека и не выбирает вариант автоматически. CLI принимает --limits: в примере задан лимит активного времени 1800 секунд. Бюджет брифа — бюджет продукта, Limits.budget — отдельный лимит внешних API; не смешивать их.

Если нужен режим только с разрешёнными материалами, поместите TXT/Markdown в `materials`, укажите `APP_RESEARCH_FILES=["market.md"]`. Без Tavily и без прочитанного файла research остановится с incomplete и объяснением. Поисковые ссылки пользователя берутся из текста брифа и читаются через Tavily Extract. Ключи задаются только локально и в Git не включаются. Файлы выбирает оператор; модель не задаёт путь и не читает соседние каталоги.

## Роли и данные

- Аналитик: извлечение возможностей, происхождение со слов пользователя, существенные вопросы; отсутствующие функции не становятся available.
- Исследователь: сначала вопросы и поисковые запросы, затем отдельные Search и Extract, затем claims с дословными цитатами. Кандидат поиска не считается прочитанным источником.
- Продуктовый стратег: три направления, критерии, возражения, ограничения и чувствительность рекомендации. Выбор сохраняет руководитель.
- Коммуникационный стратег: для каждого варианта сообщения и эксперименты, связь capability → message → claims → channel → experiment.
- Критик: смысловая проверка моделью плюс проверки кодом. ReviewIssue содержит конкретный объект, основание, исправление и этап возврата. Прежний дефект остаётся до повторной проверки.
- Сборщик: программно собирает Markdown в Artifact.summary из актуального брифа, выбранного варианта, доказательств и экспериментов. Не добавляет новые выводы. Участник 3 использует структурированные данные и summary для renderer/выгрузки.

JSON Schema ответа роли строится из contracts/schema.json; передаются только транзитивно необходимые определения, без схем API и чужих сущностей. Для OpenRouter пример .env задаёт 8192 выходных токенов; 2048 из старого шаблона может не хватить на три подробных направления. Модель не задаёт версии, принадлежность проекту, usage-суммы, артефакты или пользовательское решение. Источники создаются исключительно инструментами. Статус внешнего факта требует веб-доказательства; цитата должна входить в сохранённый фрагмент. Наличие цитаты не доказывает смысловую поддержку — её проверяет критик и независимый оценщик.

## Источники и ограничения инструментов

Транспорт Tavily реализован через httpx, без новой зависимости. Основание: [Search](https://docs.tavily.com/documentation/api-reference/endpoint/search), [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract), проверены 10 ноября 2026 года. Обрабатываются частичные успешные ответы и отсутствующие страницы. API-ошибки и использование сохраняются без запросов, ключей и сырых ошибок провайдера.

Ограничения по умолчанию: два поисковых запроса, пять веб-источников, 8000 символов на источник, 2 MB на HTTP-ответ, 200 KB на UTF-8 файл, 120000 символов контекста. Повторы URL без fragment и с default port устраняются; совпавшие прочитанные фрагменты сводятся к одному источнику со списком зеркал в origin_note. Перепечатки разных URL требуют смысловой проверки общего происхождения; это не автоматический детектор плагиата. Даты публикации, которых сервис не передал, остаются null. Дата получения фиксируется кодом. Для больших материалов сохраняется ограниченный фрагмент и честное указание об ограничении.

Внешний текст передаётся только как JSON-данные под системной инструкцией роли. У модели нет собственного доступа к сети, shell и файлам. Это уменьшает последствия prompt injection, но не является математической гарантией устойчивости модели; для production нужна независимая атакующая проверка.

## Лимиты и учёт

Usage создаёт A3 для модели и UsageRecorder для инструментов, без повторного начисления агентом. Известная стоимость локального чтения — ноль; стоимость Tavily без тарифного снимка — unknown. Codex по подписке также не объявляется бесплатным. Точные фактические модели и токены смотрите в Usage, настроенную модель/алиас — в StageSpec и артефакте.

`agent-limits.sqlite3` рядом с данными содержит устойчивые резервы по run_id. Они не снимаются после ошибки/перезапуска. Для OpenRouter заранее резервируется 1+max_retries попыток; это может остановить раньше фактического лимита, но не разрешает лишние повторы. Search и Extract вместе расходуют max_search_calls. Время ожидания человека исключено из активного времени; незавершённый при падении этап учитывается консервативно до восстановления. Проверка времени выполняется на границе внешних вызовов, текущий запрос ограничивает тайм-аут адаптера. Это не жёсткое прерывание общего wall-clock посреди запроса.

При непустом Limits.budget внешние вызовы останавливаются: без верхней оценки провайдера нельзя гарантировать денежный предел. Для запуска с ограничением количества используйте budget=null. Финансовое управление A8 остаётся задачей платформы. Резервный журнал нельзя удалять во время активных запусков.

```bash

```

Режимы с одинаковыми брифом, источниками и claims: один вызов, процесс без критика, однократная критика и полный ограниченный цикл (подробности актуальной версии ниже). Оценка использует production-маршрутизацию и заканчивается на selection без обхода человеческого выбора. Результаты, идентификаторы использования и обнаруженные кодом дефекты сохраняются; перед сравнением зафиксировать APP_MODEL_NAME. Реальные вызовы расходуют доступ провайдера. Проводить минимум на трёх кейсах, по возможности несколько повторов. Польза не объявляется без измерений.

Рубрика ручной оценки 0–2 по каждому пункту: подтверждение существенных утверждений, содержательные различия вариантов, сила возражений, соблюдение ограничений, связь обещаний с продуктом, измеримость экспериментов, понятность выбора. Отдельно считать невозможные обещания, неподтверждённые эффекты, время и стоимость. Скрыть mode от оценщика; опубликованные fixtures — данные разработки, не независимая приёмка участника 3.

## Исправления по ревью от 11 ноября

Текущая фабрика сохраняет манифест `strategy-agents-v2`, версии этапов `*-v2` и инструкции `prompts/*-v2.md`. Старые промпты v1 сохранены без изменений. Продолжать старый активный Run новым манифестом нельзя: завершите его прежней версией кода либо создайте новый запуск. Общие контракты и правила архивных ссылок хранилища не изменены.

Повторное чтение неизменённого источника сохраняет его версию и первоначальную дату получения; сам повторный вызов остаётся в Usage. Если фрагмент изменился, доказательства замечаний обновляются только после проверки дословного вхождения цитаты. Исчезнувшие цитаты убираются из текущего evidence с явной записью причины и первоначальной ссылки в explanation; исходная версия ReviewIssue остаётся в архиве A4. Утверждение без сохранённой цитаты получает unverified, а не восстановленную поддержку.

`effective_context` — совместимое представление текущих условий без перезаписи BriefVersion. Оно содержит исходный бриф и последние ответы с исходными вопросами, ID ввода и историей замен. Модель получает порядок приоритета: последний ответ на тот же вопрос уточняет первоначальные данные. Отчёт отдельно показывает действующие ответы, а прежние поля помечает как исходные. Произвольные строки не разбираются эвристически в числа/даты. Эти поля доступны через уже существующие StageContext.inputs и Artifact.summary; новый API не требуется.

URL извлекаются из исходных строк брифа и действующих ответов до JSON-сериализации. Кандидаты поиска сохраняют принадлежность вопросу/запросу. Чередование групп ограничивает общий набор; для вопроса без прочитанной страницы сохраняется причина (пустая выдача, лимит или сбой Extract). Источник-двойник не расходует второй слот одного URL; совпавшие тексты сохраняют сведения о зеркалах.

Релевантные резюме `stage_summaries` передаются следующим ролям и сборщику. Отбираются только current-артефакты того же проекта, Run и версии брифа с актуальными ссылками на сущности; диагностические артефакты исключены. Рекомендация системы, отказы от альтернатив и чувствительность выводятся отдельно от пользовательского решения.

### Оценка полного цикла

`compare_agents` теперь запускает изолированные A4/A5-процессы с одинаковыми сохранёнными источниками, утверждениями и уточнениями. Входные evidence копируются в оценочное хранилище как версия 1, исходные координаты и тексты полностью сохраняются в `input.json`. Перед запуском необходимо задать точный APP_MODEL_NAME. Если есть уточнения, передавайте `--inputs inputs.json` из сохранённого запуска.

- `single`: один модельный вызов для вариантов, сообщений и экспериментов.
- `no-critic`: отдельные генерации вариантов и коммуникаций, без критика и цикла исправлений.
- `critic-once`: однократная критика без возвратов; это отдельная абляция.
- `full`: те же production-обработчики и Orchestrator с максимум двумя циклами исправлений, включая повторный review. Если критик возвращает research, разрешена переоценка выводов по тем же замороженным источникам; новые внешние материалы для этого режима не добавляются.

Во всех режимах сохраняются snapshot, Usage, параметры, длительность, известная/неизвестная стоимость, найденные дефекты, исправленные дефекты и остаточные замечания. Метрика кода и замечания модели не объявляются независимым качеством. Граница оценки — подготовка стратегии до настоящего выбора пользователя: runner останавливается в selection и не отправляет выбор от его имени. Неисправимый дефект остаётся blocked/incomplete. Прежнее описание full как всего трёх вызовов относится к версии до исправления и больше не действует.
