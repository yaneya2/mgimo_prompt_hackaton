# Тесты и кейсы

`tests/` — автоматические проверки схем, агентов, API, хранения, безопасности, восстановления и интерфейса. Обычный `pytest -q` и Node-тесты не должны требовать реального ключа модели или поиска. Тесты с живой моделью запускаются только явно; они расходуют лимиты аккаунта.

`evals/cases/` — зафиксированные новые задачи для сравнения режимов. `evals/results/pilot/` содержит снимки и измерения уже проведённых прогонов; [методика и ограничения](../evals/README.md). Это данные оценки, а не материалы, автоматически подключаемые ко всякому новому проекту.

`materials/` — воспроизводимые ручные кейсы. У каждого входы, отдельные контрольные расчёты и инструкция. [Комплексный ремонтный кейс](../materials/complex-repair/README.md) показывает реальные вызовы модели и Tavily; [клининговый кейс](../materials/realistic-cleaning/README.md) проверял работу с предоставленными файлами без веб-поиска. Контрольные ответы не включаются в список исследовательских файлов. История конкретного выполнения хранится в `data/` и при необходимости экспортируется в отдельный протокол, а не подменяет исходный кейс.

ZIP-копии в `materials/` — пакеты передачи. Исходником для правок считается каталог кейса. Перед передачей пакет следует заново собирать из него, чтобы не разошлись версии. Не храните ключи и реальные личные данные в кейсах.
